# Mattermost Fluent

## Обновление рабочего клиента

Пользователь разрешил самостоятельно закрывать Mattermost Fluent, заменять файлы
и запускать клиент после сборки, без повторного подтверждения. Постоянный путь:
`release/win-unpacked/Mattermost Fluent.exe`. Не оставлять обновление только в
папке новой версии: пользователь запускает клиент из постоянного пути.

После успешной сборки и проверок выполнить:
`powershell -NoProfile -File scripts/update-fluent.ps1 -SourceDirectory release/fluent-v5/win-unpacked`
(подставить каталог новой версии). Скрипт проверяет пути и контрольные суммы,
сохраняет старое приложение в `release/backups`, обновляет постоянный каталог и
перезапускает приложение. Профиль `%APPDATA%/Mattermost Fluent` не заменяется.

## Пятая итерация: собственная обязательная тема

Сборка: `release/fluent-v5/6.3.0/mattermost-fluent-6.3.0-win-x64.zip`.
При включённом Fluent клиент всегда применяет собственную палитру. Старое
значение `fluentTheme: server` нормализуется в графит; выбор серверной палитры убран
из настроек. Системный и светлый варианты остаются вариантами именно темы Fluent.
Отключение Fluent возвращает штатное оформление. Серверные предпочтения не меняются.

Общий resolver используется в main-процессе и внутренних окнах. Палитра охватывает
бейджи, упоминания, разделители и код. В тесте Chromium дополнительно проверяется
фактически использованный системный шрифт для русского и английского текста
сообщения: Segoe UI, а не только значение CSS font-family.
Дальнейшие задачи и незавершённая единая командная панель: [FLUENT-TODO.md](FLUENT-TODO.md).

## Четвёртая итерация: исправление редактора

Сборка: `release/fluent-v4/6.3.0/mattermost-fluent-6.3.0-win-x64.zip`.
Удалены конфликтующие правила, оформлявшие внешний `.AdvancedTextEditor` как поле
ввода. Единственная рамка теперь у `.AdvancedTextEditor__body`; textarea и внешний
контейнер прозрачны. Исправление общее для ленты и тредов; расчёт AutoHeight,
отступы под кнопки и логика отправки не меняются. Новый стенд повторяет вложенность
редактора, проверяет рамки, фокус и ширину в основной и узкой правой колонках.

Для текста и элементов управления выбран Segoe UI, для сообщений — 15px / 1.5.
Шрифты иконок и блоков кода сохранены.

При диагностике локальных параметров оформления обнаружен `fluentTheme: server`.
Именно этот выбранный режим сохраняет синие серверные цвета. Его название уточнено:
«Сохранить цвета сервера (без палитры Fluent)». Для графитового оформления выберите
«Fluent — тёмный графит». Пользовательский файл конфигурации не перезаписывался.
Объединение двух верхних строк в одну этой итерацией не выполнено.

## Третья итерация: Fluenty-inspired

Сборка: `release/fluent-v3/6.3.0/mattermost-fluent-6.3.0-win-x64.zip`.
Нейтральный графит и голубой акцент, тонкие разделители вместо рамок панелей,
единое оформление редактора, ленты и RHS. Повторный логотип в переключателе
продуктов скрыт, сама кнопка и меню сохранены. Верхние строки визуально объединены
цветом, но физически остаются двумя строками в разных WebContentsView.

Исправлено взаимодействие со старыми `applyTheme/changeCss`: эти версии задают
часть цветов напрямую, а не через переменные. Добавлены явные стили основных
поверхностей. Переменные палитры вставляются с пользовательским приоритетом CSS,
чтобы перекрывать inline important без изменения серверного DOM-стиля.
Регрессионный тест создаёт такие правила после загрузки CSS и проверяет реальные
цвета ленты и RHS, а также переключение цвета через production preload.

Выбор цвета: настройки клиента → Fluent → Тема клиента → Светлая/Тёмная.
Материал окна (Mica/Acrylic) управляет прозрачностью, это отдельная настройка.
Проверки используют синтетические данные; результат на рабочем сервере ещё
нужно подтвердить. Полного объединения поисковой панели и заголовка окна пока нет.

## Вторая итерация

Общая локальная палитра: системная, светлая, тёмная или исходная тема Mattermost.
Переключение применяется к веб-содержимому, стартовому экрану, подключению сервера
и настройкам клиента. Серверные настройки темы не перезаписываются.

Оформление теперь распознаёт страницы входа и другие маршруты с оболочкой
`header-footer-route`, даже когда списка каналов ещё нет. Изменены фон, карточки,
типографика и поля. Непрозрачные вложенные слои Channels убраны; материал задаётся
для основных панелей. Подсветка каналов сохраняет переход через промежутки строк.

Сборка этой итерации: `release/fluent-v2/6.3.0/mattermost-fluent-6.3.0-win-x64.zip`.
Проверены настоящий стартовый экран и подключение сервера, смена темы через IPC,
а также Chromium-регрессии палитры, входа и сохранения введённого текста на
синтетическом стенде. Проверка реального рабочего сервера и измерение FPS не
проводились; полная матрица серверных версий остаётся отдельной проверкой.

## База и первая итерация

Локальный форк официального Desktop **6.3.0**, исходный коммит
`2c06d780b010c5d3a26bf6753fe048e8963e9e27`.
Ветка: `fluent/6.3-redesign`. Официальный репозиторий подключён как `upstream`.

## Запуск

Готовая Windows x64 сборка: `release/win-unpacked/Mattermost Fluent.exe`.
Для переноса нужна вся папка `win-unpacked` или ZIP из `release/6.3.0`.

Профиль: `%APPDATA%/Mattermost Fluent`. Профиль обычного Mattermost не переносится
и не изменяется. Добавьте адрес рабочего сервера и войдите обычным способом.

В настройках приложения (`Ctrl+,`) откройте **Оформление**:

- **Fluent** — включение всего локального слоя;
- **Solid / Mica / Glass** — материал окна;
- **Плавные анимации** — движение подсветки и появление панелей.

Быстро вернуть штатный интерфейс: **Вид → Оформление Fluent** или `Ctrl+Alt+F`.
Настройки применяются без перезагрузки страницы и сохраняются локально.

## Что реализовано

- Нативные Mica и Acrylic через Electron; непрозрачный запасной режим на других
  ОС, Windows до 11 22H2, при отключённом GPU и уменьшении прозрачности.
- Полупрозрачная навигация, оформление поля ввода, сообщений, меню и диалогов.
  Сохранена серверная палитра, включая пользовательские темы.
- Одна движущаяся плашка подсветки; обновление геометрии не чаще одного раза за
  кадр. Нет обновлений React/Redux от движения мыши и постоянного цикла отрисовки.
- Зарезервированное место для меню строки: наведение не меняет правый отступ.
  Значки непрочитанного сохраняют измеряемый размер.
- Учёт системного уменьшения движения; в режиме высокой контрастности внешний
  webapp остаётся штатным.
- Отдельное имя, профиль, Windows AppUserModelID и идентификатор MSI.
  Автообновление до официального бинарного клиента отключено.

## Граница совместимости

Серверная часть, запросы, авторизация, WebSocket, DesktopAPI, version checks и
загрузка webapp остались от Desktop 6.3.0. Никакой плагин на сервере не нужен.
Слой запускается только на URL настроенного сервера, включая проверку границы
подкаталога, и только при обнаружении знакомой структуры Channels.

Поддерживаются контейнеры `SidebarContainer` и `sidebar-left` с существующими
`SidebarChannel` / `SidebarLink`. При неизвестной структуре webapp продолжает
работать без Fluent. Это сохраняет возможность подключения, но **не означает,
что полный визуальный редизайн проверен на каждой версии сервера**.

Страница входа и другие сайты не оформляются. Содержимое сообщений, имена,
порядок строк, обработчики ссылок и редактор не заменяются. IPC настроек идёт
только из main в изолированный preload; системные API в страницу не добавлены.

## Сборка и проверки

Node.js 24; npm; Windows x64:

```powershell
npm run setup:windows
npm run check
npm run build
npm run test:fluent
npm run package:fluent
```

`setup:windows` устанавливает зависимости и использует два неизменённых native
модуля из официального Windows x64 релиза 6.3.0. SHA-256 ZIP проверяется перед
извлечением. Это обход отсутствующего компонента Visual Studio ATL на текущей
машине; обычная upstream-сборка модулей с установленным ATL также возможна.
При обновлении базы необходимо пересмотреть закреплённые версии и хеш.

На этой машине упаковщику дополнительно понадобилось извлечь Windows-инструменты
из его проверенного кеша `winCodeSign-2.6.0`, исключив каталог `darwin`: создание
символических ссылок macOS было недоступно. Это настройка локального кеша сборщика,
не изменение приложения. При аналогичной ошибке можно включить поддержку symlink
в окружении сборки либо извлечь только необходимые Windows-инструменты.

`test:fluent` запускает реальный Chromium/Electron с тестовой страницей и строгим
CSP, проверяет область применения, смену страниц, движение, сохранение черновика,
очистку DOM и production preload. Все данные синтетические. Изображения в
`artifacts/fluent-preview-*.png` — тестовый стенд, **не снимки рабочего сервера**.

Проверено в этой итерации: `npm run check` (81 набор, 1328 тестов), проверки
Chromium и production preload, сборка Windows ZIP, запуск готового EXE и
изменение/чтение настроек через штатный IPC в отдельном тестовом профиле.
Первый запуск выдаёт штатное сообщение об отсутствующем `bounds-info.json` и
сообщение `clearAppCache: Object has been destroyed`; приложение продолжает
работу. Эти сообщения не исследованы как отдельные upstream-проблемы.

## Дальнейшая работа

Это первая запускаемая итерация, а не завершённая замена всех экранов.
Нужны испытания на реальном сервере: вход/SSO, треды, уведомления, звонки и
демонстрация экрана, вложения, несколько серверов, масштабирование и мониторы.
До профилирования на рабочем сервере нельзя заявлять измеренный прирост FPS.

Следующий этап — адаптация оставшихся компонентов под конкретные серверные
версии, профилирование длинного списка и ленты, локальные настройки плотности,
палитры и интенсивности материалов. Обновления upstream переносятся отдельно
с повторной проверкой совместимости. GitHub-репозиторий форка пока не опубликован.
